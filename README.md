# Embedded C Toolkit

[![tests](https://github.com/fatinnihal532-hub/embedded-c-toolkit/actions/workflows/ci.yml/badge.svg)](https://github.com/fatinnihal532-hub/embedded-c-toolkit/actions/workflows/ci.yml)

Four modules that turn up in almost every firmware project, written as portable
C99 with no hardware dependencies, and covered by unit tests that run on a
laptop. Every push is compiled with GCC and Clang, run against the test suite,
and then cross-compiled for an ATmega328P to prove the code still fits an 8-bit
target.

| Module | What it solves | AVR code size |
|---|---|---|
| `ring_buffer` | byte FIFO between an interrupt and the main loop | 492 B |
| `debounce` | one clean press out of a bouncing contact | 102 B |
| `filter` | exponential moving average and median of three | 482 B |
| `pid` | discrete PID with anti-windup and derivative on measurement | 964 B |

## Why unit test firmware at all

Firmware is usually debugged by flashing a board and watching an LED. That
works until the bug is a wrap-around in a ring buffer that only appears after
two hours of traffic, at which point the board tells you nothing useful.

Everything in this repository is ordinary C. It has no `#include <avr/io.h>`,
no `digitalWrite`, no `millis()`. That is a design decision, not an accident:
code with no hardware in it can be compiled for the laptop and exercised
thousands of times in a second. `test_ring_buffer.c` pushes and pops 200 bytes
through an 8-byte buffer to force the index wrap repeatedly, which is the one
test that catches an off-by-one in `next_index()`. On real hardware that bug
might take days to show itself.

The hardware-dependent layer stays thin and lives in the project that uses it.
This separation is the same one that makes the rest of the code testable.

## The parts worth reading

**`ring_buffer`** is a single-producer, single-consumer FIFO. The producer only
ever writes `head`, the consumer only ever writes `tail`, and the data is
written before the index is advanced. That ordering is what lets an interrupt
and the main loop share it without disabling interrupts. The capacity is one
byte less than the array, because that spare slot is what makes `head == tail`
mean empty rather than full.

**`debounce`** uses an integrator rather than a timeout. The counter climbs
while the input reads active and falls while it reads inactive, and the output
only changes at the two ends of the count. Short noise never travels far enough
to flip it. One counter per button, no blocking, and it degrades gracefully on
a genuinely dirty contact.

**`filter`** has both an exponential moving average and a median of three,
because they fail in opposite situations. The average is the right tool for
constant hiss and the wrong tool for a single wild sample, which drags it off
course. The median ignores the spike completely and is the right tool when an
ADC shares a board with a switching regulator.

**`pid`** differentiates the measurement instead of the error, so a set-point
change produces no spike in the output, and freezes the integral while the
output is saturated, so a long approach to the target does not build up a term
that has to be unwound later. `test_pid.c` checks both properties directly:
one test moves the set point with the measurement held still and asserts the
output does not move at all.

## The test harness

About forty lines in `tests/test_harness.h`, with no dependency to install.
`CHECK`, `CHECK_EQ_INT` and `CHECK_NEAR` print the file, line and test name
when they fail, and `main()` returns non-zero if anything failed, which is all
that a CI job needs to fail the build.

## Continuous integration

`.github/workflows/ci.yml` runs on GitHub's servers on every push:

1. build and test with GCC
2. build and test with Clang, because each compiler warns about things the
   other misses
3. cross-compile the modules for an ATmega328P with `avr-gcc`, so a change that
   relies on a 32-bit `int` or a large stack frame is caught immediately

The badge at the top of this file is generated by that workflow.

## Use it

```bash
git clone https://github.com/fatinnihal532-hub/embedded-c-toolkit.git
cd embedded-c-toolkit
make test          # compile and run every suite
make lib           # build build/libembedded.a
```

To use a module in a project, copy the `.c` and `.h` pair and include the
header. There is nothing else to configure.

```c
#include "ring_buffer.h"

static uint8_t storage[64];
static ring_buffer_t rx;

void uart_init(void)  { rb_init(&rx, storage, sizeof(storage)); }
void uart_isr(void)   { rb_push(&rx, UDR0); }      /* called from the ISR */

bool uart_read(uint8_t *byte) { return rb_pop(&rx, byte); }
```

## File layout

```
src/            the four modules, one .c and .h pair each
tests/          one suite per module plus the test harness
Makefile        build, test and library targets
.github/workflows/ci.yml
```

## Possible extensions

- Add a cooperative scheduler module and test it against a fake clock
- Measure line coverage with `gcov` and publish it alongside the badge
- Add a fuzz target that throws random push and pop sequences at the ring
  buffer and asserts the invariants after each one
